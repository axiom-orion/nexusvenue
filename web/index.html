Turning siloed CRM rows into grounded sales intelligence

Enterprise event sales is won on relationships: the agency with a track record at a sister property, the account spending across three cities under three legal names. Property-siloed CRMs miss all of it. NexusVenue rebuilds those facts as a knowledge graph and puts a grounded, evaluated LLM advisor on top.

The problem

Three CRMs that were never integrated

Each property runs its own Salesforce-shaped org. The same customer is entered under a different legal-name variant at each one, the same planner is duplicated with inconsistent spellings, and the knowledge that wins deals is trapped in free-text booking notes.

Entity resolution

Collapse the variants, keep the provenance

RapidFuzz token_sort_ratio ≥ 87 plus union-find clustering (after legal-suffix normalization) merges name variants into one canonical node per real-world entity. Contacts collapse on email. Every canonical node keeps its aliases and source_ids so nothing is lost. Names alone can't connect an abbreviation to its company, so accounts whose contacts share a corporate email domain and an industry are joined too, with name evidence always taking precedence.

LLM-as-a-judge

Grade the output, across model families

A reference-less adversarial judge scores each blueprint against the retrieved context only, and enumerates any claim the context doesn't support. It runs on Claude, Gemini and Grok, because a judge over-rates its own family's output (self-preference bias), so cross-family agreement is the real signal.

The gate

The two numeric thresholds are enforced in code for every model family. The model only makes the call a number can't: whether a hallucination it listed is material.

Deterministic eval

Retrieval precision / recall @k, in CI

The judge catches generation failures; a seeded gold set catches retrieval regressions deterministically: no keys, no LLM, and it runs in CI on every commit. These numbers are computed here with the offline hash embedding backend.

Incremental sync

The next business day, without a rebuild

A watermark on last_modified pulls only changed rows. The hard part is entity resolution: a delta row must resolve against canonical nodes already in the graph, or the two paths disagree and the graph forks. Each change below exercises a different code path, and all of it is idempotent.
